# E49AA — calibrated pairwise discovery from observed hard-MATH solutions

**Status: PREREGISTERED BEFORE E49Y COMPLETES — 2026-07-26**

## Motivation and activation rule

E49Y asks two whole-set partitions to agree exactly before a natural
multi-route menu can be proposed.  Its first twenty completed hard-MATH
cases produced no qualifying menu: failures were missing assignments,
order-sensitive pairwise relations, or fewer than two repeated clusters.
Those failures remain failures and E49Y's gate will not be relaxed.

E49AA is a contingent replacement that may run only if the final E49Y result
does not contain ten bidirectionally executable problems.  It changes only
offline route discovery.  The eventual training reward, finite-menu
execution gate, canonical bank, novelty term, and normalized E46 Haarnoja
controller remain unchanged.

## Calibrated clustering contract

Run the exact E47W pairwise-veto canonicalizer with SHA-256
`91a1a8fdc3b29fa49b1089154f5955ec2d9e759cc85e94b35bc7d101d81bf988`.
The frozen E47W analysis has SHA-256
`3ad930355d4ef3cc30f153035db3cfdca5bf8290566b00fe3383111c4c7455d6`
and gate status `pass`: all nine automatic checks pass, injected false-new is
0/150, blinded analyst-same false-new is 0/9, the known invalid witnesses are
rejected, and every semantic regression passes.

For one problem, submit all selected responses as one group.  The
canonicalizer must:

1. pass each response through two derivation-integrity audits;
2. propose boundaries using two order-permuted full-context partitions;
3. conservatively coarsen those boundaries using its two independently
   permuted, reasoned pairwise novelty-veto audits; and
4. emit keys only for responses that survive its fail-closed contract.

A problem is cluster-eligible only when at least two emitted keys each have
at least two natural member responses.  Retain the two largest such
components, breaking ties by key.  Rank problems by minimum retained
component size descending, combined retained size descending, then exact
source index ascending.

## Menu and executability gate

For every cluster-eligible problem, ask the same frozen Qwen72 endpoint to
convert only the two observed components into an S1/S2 finite action menu.
Each route must cite one to three member response IDs.  Proposed or repaired
routes are forbidden.  Two independent menu audits must both establish:

- each action is mathematically sound and problem-specific;
- the action combo is sufficient to derive the reference answer;
- every cited response really executes the stated combo;
- S1 and S2 are genuinely distinct rather than paraphrases or routine
  algebraic reparameterizations; and
- neither route leaks the final answer.

For each double-audited menu, force the 0.5B base model to attempt each route
eight times.  A success requires both exact answer validation and assignment
to the requested route by the exact frozen E49T finite-menu canonicalizer.
Wrong-route successes are recorded and do not count.  A problem is
bidirectionally executable only if each route succeeds at least once.

E49AA passes only with ten bidirectionally executable problems.  Selection is
the first ten passing problems in the frozen rank order.  No failed route may
be relabeled, simplified, or replaced after observing forced-generation
outcomes.
