# E49D xgrammar audit-schema amendment — 2026-07-24

**Status: FROZEN BEFORE ANY E49D TRAINING LAUNCH**

During the pending-only toy retry, the frozen vLLM/xgrammar server completed
all eight train-row certifications and then terminated on a fatal structured
grammar compilation error:

```text
RuntimeError: EBNF parse error ... Expect element, but got character: :
```

The failure occurred while compiling the audit schema's long unrolled
`maxLength` string grammars. Five requests then failed by connection refusal.
No E49D dataset or training job was launched. The 95 durable certifications
completed before the engine failure remain valid.

The server-side audit schema continues to constrain the exact JSON object
shape, field names, array sizes, IDs, booleans, and enums. Only its
`minLength`/`maxLength` string annotations are removed. A deterministic local
validator now enforces the same nonempty-string requirements and the same
128/256/512-character bounds before an audit can certify any route. The same
validator is invoked when durable evidence is recomputed, so malformed or
overlong newly generated bytes fail closed. New audits carry the explicit
transport marker `local_string_bounds_v1`. Pre-amendment v4 audits, which
cannot carry that later marker, retain their original exact-shape,
nonempty-text recomputation contract; four already accepted records contain a
single explanatory field slightly above a later transport cap, and remain
valid rather than being retrospectively relabeled. They still have the same
answer-bound soundness and pairwise-distinctness evidence.

Proposal schemas are unchanged. Mathematical execution, double auditing,
maximal-clique certification, singleton fallback, policy data, runtime
validation, reward, E46 controller, cohorts, schedule, and gates are
unchanged. This is a transport-compatible relocation of identical validation
from a crashing grammar compiler to deterministic local code.
