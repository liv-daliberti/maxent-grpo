# E63: cross-domain validator-preserving transform pilot

## Question

E62-R9 showed in Python factors that a model-authored verified response can be
transformed into independently verified support and that replay can transfer
that support into correct neutral-policy multiplicity. E63 asks whether the
same actuator contract works on Graph Coloring, Countdown, and the actual
MathIR action-menu benchmark before any three-seed cross-domain expansion.

This is a one-seed mechanism and safety gate, not stable-success evidence.

## Frozen cohort

E63 contains six fresh Qwen2.5-0.5B-Instruct jobs: one exact same-seed control
and one treatment for each of:

- Graph Coloring, 192 updates / one prompt pass;
- Countdown, 384 updates / one prompt pass;
- MathIR action menu, 384 updates / one prompt pass.

Every run uses seed 9011, 16 neutral samples, physical microbatch four with
four accumulation steps, four independent sampled K=8 evaluation draws at
quarter-pass cadence, checkpoint/resume at that same cadence, and no state
from E61 or E62. The control is
`verified_first_bootstrap_local_canonical`; the treatment is
`verified_counterfactual_canonical`.

## Frozen transformations

Every treatment transformation starts from a response generated by the
current policy that passes both task reward and the ordinary executable
validator.

- Graph Coloring tries safe local recolorings and two-color component swaps
  containing no public fixed vertex. Every resulting assignment is rechecked
  against every edge and partial-color constraint.
- Countdown applies value-preserving signed AST rewrites such as
  `a + b -> a - (-b)` and paired operand negation for multiplication or
  division. Every result is rechecked for exact number use and target value.
- MathIR applies adjacent action swaps and a fixed edit-distance-one
  neighborhood of the model-selected action path. This is not exhaustive
  sequence enumeration. Every result is executed by the ordinary MathIR
  interpreter, which rechecks intermediate states and the terminal equation.

Candidates are tokenized, decoded, and revalidated to the same canonical
outcome before atomic support-only admission. Current/prior known outcomes are
discarded. The fixed replay capacity reserves slots for model-generated
outcomes and caps transformed storage compute; it is not a desired support
size.

If the fixed transform neighborhood yields no novel valid outcome and replay
capacity remains, the untouched-original-prompt temperature sweep from
E62-R7 remains a fallback.

## Information firewall

Training may read only:

- the current prompt and public executable task constraints;
- responses generated by the current policy;
- ordinary task reward and the executable validator;
- fixed sampling, storage, and transformation compute limits;
- the existing model-entropy and replay-surprisal sensors.

Training may not read:

- a gold answer list or exhaustive support;
- `num_completions`, `valid_mode_count`, or another desired mode count;
- desired entropy or normalized entropy;
- evaluation coverage, pass@K, correctness@K, or distinct@K;
- an alpha projection, coefficient cap, or ground-truth-derived "how high"
  value.

Both replay controllers and the open-set coefficient remain unprojected.
Transformed and fallback proposal rows sent to PPO must be exactly zero.

## Gate

Each job is bound to an exact Slurm ID, data hash, protocol, launcher, source
snapshot, execution snapshot, and manifest. The live audit fails on a crash,
non-finite telemetry, binding mismatch, neutral-RNG mismatch, projection,
forbidden feedback, proposal row in PPO, altered neutral PPO width, invalid
transform accounting, or a treatment that never admits a novel transformed
outcome after observing an eligible anchor.

The mechanism signal is evaluated only after training and never fed back.
For each domain, the treatment must land post-initial
`distinct_correct@8 > pass@8` and terminal distinct correct no lower than its
same-seed control. A clean pass authorizes a fresh three-seed, twelve-pass
comparison across all four domains, including Python factors. A failure
triggers mechanism diagnosis rather than selection of a hidden support target.
